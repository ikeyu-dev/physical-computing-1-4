## 制作の背景

今学期（2年秋）がフィジカルコンピューティング工房の最後の履修。過去の作品は、1-1が表情で答えるゲーム、1-2が手の形で実物の車を動かすシステム、1-3が全身で自転車を操作する交通ルール学習ゲームだった。各リポジトリは、このリポジトリと同じ親ディレクトリにある。

1-3の改良も検討したが、ユーザーは新作を作りたい気持ちがやや強かった。基本的に遊ぶ人は1人。旧作の「案内が小さい」「状況の変化が唐突」といった反省は参考にできるが、自転車ゲームの機能を引き継ぐ必要はない。

## ユーザーが示した方向性

- 実物の模型ではなく、画面の中のペットでよい。Raspberry Piやモーターは使わない方向に変更した。
- Figmaの見た目を実装に使いたい意向がある。既存のこもりをSVG素材として利用する案を説明済み。
- デザインは「素朴な感じ」。ユーザーから「AI臭くならないように」と要望がある。
- こもりは「喋らないけれど、気持ちは伝わる」方向で合意した（2026-10-02）。セリフの吹き出しは使わず、目線や動きで表現する。操作案内を短く表示する案は、表示方法も含めて未確定。
- 「たまごっちっぽい」という理解は近い。ただし、餌やりや長期的な成長を備えた育成ゲームにする決定はしていない。

目的案は、手への反応から生き物らしさや愛着を感じられる体験を作ること。動きの速さや反応の間を工夫し、相手の様子を見ながら接し方を変えたくなる作品を目指す。現状は勝敗や得点のあるゲームより、触れ合いを中心とする体験型作品に近い。

## 操作と反応のたたき台

次の表はユーザーに提示済みの案。反応の細部や判定値は未確定で、実装済みではない。

| ユーザーの操作           | こもりの反応案           |
| ------------------------ | ------------------------ |
| 手を映して静かに待つ     | 殻から少しずつ顔を出す   |
| 手をゆっくり左右に動かす | 目や顔で手を追いかける   |
| 手を急に動かす           | 驚いて殻に隠れる         |
| 穏やかな動きを続ける     | 徐々に慣れて反応が変わる |

開始・終了・やり直しは画面のボタンで操作する案。手の位置を画面上の小さな印で示し、こもりとの画面上の距離と手の動く速さを使って判定する案も提示している。カメラに手を近づける奥行き操作や実距離の測定は、初期案に含めていない。

「急に動かす」の速さ、顔を出すまでの待ち時間、慣れの増減などは、実際の操作感を見て調整する。手の検出が途切れたときや認識の揺れを、驚きとして扱わない設計も検討する。

## キャラクターとデザイン

こもりは岩のような外側に隠れ、様子をうかがって顔を出すイメージ。ラフでは顔を出しているが、開始時は隠れていて目だけが見える案を説明した。外側が体の一部の「殻」なのか、住居の「岩穴」なのかは未確定。慣れたら全身で外へ出て歩くことも、まだ採用していない。

細い線、白に近い背景、控えめな色、手書き風の見出しを用いる。既存ラフの見出しはKlee One、本文はNoto Sans JP。顔を描き込みすぎず、目や体の小さな動きで気持ちを伝える。数値や長い説明を常時並べるより、キャラクターの反応を見せる方向。

短い文言の例は「手を、ゆっくり。」「寝ちゃった。」。ただし既存の文言をすべて残す決定ではない。実装時には画面内の操作に合うかを確認する。

## 終了とプレイヤー交代の相談（2026-10-01）

### ユーザーの相談と、もらったアドバイス

ユーザーは、途中でプレイヤーが入れ替わる場合の扱いと、ゲームの終了条件を詰めたいと考えている。リロードで状態をクリアする方法は簡単だが、それだけでは世界観が壊れてしまうという懸念がある。好感度ゲージを数値として保持する案も挙げた。画面にゲージを表示するか、リロード後にも値を保存するかは未確定。

ユーザーから、次のアドバイスをもらったと共有があった。助言者はこの会話では示されていない。

> 一定時間操作がなかったら（好感度が下がって）殻に再度こもる

このアドバイスは検討材料として記録する。採用が決まった仕様ではない。

### 当初の提案：安心度と不在時間を分け、眠ったところで区切る

この節と前述のボタン操作は相談当初の案。ボタンと好感度MAX時の扱いについては、次節に後続の相談を記録している。

以下はアシスタントの提案であり、未採用。好感度に相当する数値を内部で持つ案は、反応を段階的に変えるために使える。ただし、この作品では「今どれくらい安心しているか」と捉えると、初対面に戻る演出にもつなげやすい。仮に0〜100の安心度を持ち、穏やかな触れ合いで上がり、急な動きで下がる形を考える。数値は画面に出さず、顔を出す深さや目線で伝える案を推奨する。

安心度が低いだけでは終了しない。驚いて隠れても、プレイヤーが静かに待てば再び顔を出せるようにする。安心度が最大になった場合も、触れ合いは続けられる。

自動終了には、手が見えなくなってからの時間を別に使う。「手を映して静かに待つ」は有効な接し方なので、動きがないことを不在と判定しない。認識が一瞬途切れただけでも終了させない。カメラ停止や認識エラーは、通常の不在とは分けて案内する。

| 状況                               | 反応・終了の案                                       |
| ---------------------------------- | ---------------------------------------------------- |
| 手が見えなくなって数秒             | そのまま待つ。安心度はすぐに下げない                 |
| 手が見えない状態が10〜15秒ほど続く | 辺りを見回し、安心度がゆっくり下がって殻へ戻り始める |
| 合計30秒ほど手が見えない           | 殻の中で眠り、今回の体験を終了する                   |
| 眠る前に手が戻る                   | 終了を取り消し、その時点の安心度で触れ合いを続ける   |
| 「おやすみ」を押す                 | 殻に戻って眠る演出を経て終了する                     |

時間は操作感を試すための仮値。自動終了は安心度が0になることを条件にせず、不在時間で判断する。よく慣れた状態でも、無人のまま長く残らないようにするため。

終了後は、眠っている間に安心度と直前の手の位置・速さなどの履歴を初期化する。「はじめまして」で次の体験を始める構成なら、交代時にもリロードが要らない。値はまず体験中だけ保持し、リロードをまたぐ保存は加えない案。

手の位置と動きだけを使う構成では、すぐに入れ替わった人を別人として判定する前提を置かない。途中で交代する場合は「おやすみ」→「はじめまして」で区切る。終了せず手を引き継いだ場合は、同じ触れ合いが続く扱いにする。

未確定なのは、ゲージ表示の有無、不在から終了するまでの時間、交代時に毎回初対面へ戻すかどうか。時間制限で必ず終了させる案も考えられるが、まずは不在による自動終了と「おやすみ」による任意終了を組み合わせる案を推奨する。既存ラフの「2〜3分」は引き続き確定した制限時間ではない。

### 後続の相談：好感度MAXからN秒で眠る案

ユーザーは画面上のボタンが世界観を壊しそうだと指摘し、「好感度がMAXになってからN秒経ったら、おやすみになる」案を出した。アシスタントは、安心した反応をしばらく楽しんでから、あくびをして殻に戻り眠る流れを提案した。

一度MAXに達してから20〜30秒ほどで眠ること、途中離脱には不在による終了を残すこと、睡眠後に手が一度消えて再び現れたら次の体験を始めることは、アシスタントの未採用案。N秒の値と計測条件、再開方法は未確定。途中で人が交代した場合は好感度を引き継ぐ案も説明した。

## 画面を触る子への案内の相談（2026-10-02）

ユーザーから、教授に「小さい子はどうしても画面を触ってしまう。そこはどう切り分けるか」と指摘されたことが共有された。「画面と現実の区別が曖昧なのか」という点は相談中の疑問であり、原因として確認された事実ではない。

手を動かす場所を展示の配置と反応で伝えるため、アシスタントは以下を提案する。いずれも未採用。

| 案                         | 具体的な見せ方                                             | 検討点                                                                         |
| -------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 机に手の居場所を作る       | 画面の手前に小さなマットと手の絵を置き、その上に手をかざす | 実際のカメラの認識範囲に合わせる。マットに触れる操作だと誤解されないか確かめる |
| 手を映した瞬間に反応を返す | 小さな印が手に追従し、こもりがそちらを見る                 | 画面に触れる前に、自分の手と反応の関係が伝わるか確かめる                       |
| 最初に短い動作例を見せる   | 画面から離れた手をゆっくり動かす横向きの図やアニメーション | 文字を読まなくても、画面と手の距離が伝わる表現にする                           |
| 展示の配置で距離を作る     | 画面を机の奥に置き、手前を触れ合う場所にする               | 子どもの目線、手の届き方、カメラの画角を実機で確認する                         |

まずは机上の目印と、手に対する即時の反応を組み合わせる案を推奨する。物理模型や追加センサーを導入する提案ではない。画面への接触を理由にこもりを怖がらせる案は、触ったことを罰する体験になり得るため推奨しない。接触を検知できる前提も置かない。

検証では、説明前にどこへ手を伸ばすか、反応を見て手を動かす場所が分かるか、画面を触った後でも迷わず触れ合いに戻れるかを観察する。展示配置と対象年齢は未確定。

### 待機と睡眠の動きの違い

ユーザーが次の方針を決めた。待機中は顔を完全に殻の中へ隠し、ときどき少しだけ顔を出して外をうかがい、また隠れる。睡眠中は完全に隠れたまま寝息を立てる。待機中に顔を常時出す案や、目だけを常時見せる案は採用しない。

Figmaの待機画面（`2:13`）も、顔を完全に隠した基本姿勢に更新した。睡眠画面との見た目の違いは寝息の記号と案内文。顔を出す間隔・出す量・目線の動かし方、寝息の音や動きの表現は今後調整する。Figmaは静止状態のデザインであり、待機中の動きと寝息の再生はまだ実装していない。ローカルの待機ラフも更新前なので、最新のFigmaとこの記録を優先する。

## 実装開始の指示を受けたら

まず、既存ラフのこもりを使って「手を追う・まばたき・隠れる」を試す進め方を提案している。以下はその検証観点であり、すべてを一括実装する指示ではない。

- 画面上の手の印とキャラクターの反応が結びついて見えるか。
- ゆっくり動かす／急に動かす／待つ、の違いが伝わるか。
- 検出の揺れや一時的な手の消失で、反応が不安定にならないか。
- 初めて遊ぶ人が、説明を読み続けなくても触れ合えるか。
- リセット後に次の人が初対面から遊べるか。

今後決めることは、殻と岩穴の設定、慣れた後の変化、体験の終了条件、手の印の見せ方、音の使い方、保存の有無。Figmaにある「2〜3分」や眠って終わる演出はラフ段階の提案であり、制限時間として確定していない。

実装を進めたら、決まった内容と動作確認の結果をこの文書に反映する。

## プロトタイプの作成（2026-10-05）

ユーザーの実装開始指示に基づき、React / TypeScript / Viteで作成した。PC＋Webカメラで遊び、マウスでも動きを確認できる。Figmaの既存こもりとLucideの5本指・ペールオレンジのグーパーを使用。待機・触れ合い・睡眠を同じ画面でつなぎ、操作中のボタンや好感度ゲージ、セリフは置いていない。

### 実装した範囲

- 手の位置を平滑化して画面内に表示。グーパーは実際の手の形だけを反映し、撫でる効果は変えない。
- 待機中は顔を完全に隠す。約8秒ごとに顔を少し出し、目線で外をうかがう。
- 穏やかな接近で顔を出し、撫でると安心度が上がる。急な動きで隠れ、静かに待つと回復する。
- 安心度が初めて100になって20秒後に眠る。最後の4秒にあくびをする。途中で安心度が下がっても開始した睡眠タイマーは戻さない。
- 手が消えて10秒で安心度が下がり殻へ戻る。30秒で眠る。静止した手は不在と扱わず、短い認識切れで終了しない。
- 睡眠中は顔と足を完全に隠し、殻の小さな呼吸、寝息の記号、合成した寝息音で示す。
- 睡眠中に手が1.2秒以上消えて戻ると安心度と操作履歴をリセットし、次の体験を始める。最低4秒は眠る。手が残ったままでは自動再開しない。
- カメラ許可・音の選択は準備画面で行う。Escで戻るとカメラも停止。カメラの不具合は通常の不在とは分けて案内する。
- タブが非表示の間は体験の時間と寝息を止める。映像や体験状態は保存しない。

時間、速度、判定範囲は `src/game/config.ts` に分離した。これらはプロトタイプで試すための仮値であり、ユーザーが数値まで決定した仕様ではない。途中で別の人が手を引き継いだ場合、人の識別はせず同じ体験を継続する。

### 検証と残る調整

状態遷移と手の入力処理の12件のテストを実行。マウス操作と模擬カメラによるChromeテストで、グーパー、驚きと回復、不在による睡眠、再開、実際の認識モデルの初期化、カメラ停止、カメラ拒否時のマウスへの切り替え、狭い画面での横はみ出しがないことを確認した。型検査とビルドも成功。依存関係の監査は既知の脆弱性0件。起動・検証コマンドはREADMEに記載。

残る実機確認は、人の手でのグーパー判定、手の移動量と画面の対応、急な動きの閾値、寝息の音量、終了までの時間。特に子どもが画面内の手を見て操作場所を理解できるかは、このプロトタイプだけで解決済みとはしない。コミット・push・公開は今回の依頼範囲に含めていない。
